# 07 — Stage technicien / stage d'application

**Use this when:** second or third-year internship, 4 to 8 weeks, where you were
given a real but bounded task — a script, a module, a migration, a set of
configurations, a piece of testing.

**Length:** 20–35 pages.

## Where it sits

Between `00-stage-initiation` (pure observation) and `04-pfa-annual-project` (a
project you own). You contributed something, but you did not define the problem
and you were not autonomous. The report should reflect that honestly.

| | Stage d'initiation | Stage technicien | PFA |
|---|---|---|---|
| You observe | ✓ | ✓ | ✓ |
| You execute a defined task | | ✓ | ✓ |
| You define the approach | | partly | ✓ |
| État de l'art expected | no | no | brief |
| Length | 10–20 p | 20–35 p | 25–40 p |

## Shape

| Chapter | Answers |
|---|---|
| 1. Contexte du stage | Where, and what was the assignment? |
| 2. Étude et démarche | What was the task, and how did you approach it? |
| 3. Réalisation | What did you build or configure, and does it work? |
| 4. Bilan | What came of it, and what did you learn? |

## The main trap

Inflating a bounded task into a "projet". If you wrote a deployment script,
describe a deployment script well — its constraints, its edge cases, how you
tested it. A precisely described small contribution grades better than a vaguely
described imaginary large one.
